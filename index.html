Music Composition Agent

In Development

Problem

  • — AI music tools generate output instead of assisting the creative process
  • — Built for non-musicians; useless for a working composer
  • — What's needed: a collaborator that engages with incomplete material and helps think through decisions

What's built

  • — Next.js composition studio with four workflow stages: Pre-Composition, Lo-Res, Hi-Res, Engraving
  • — Server-side Anthropic API route handles all model calls
  • — MCP server planned to expose protocol documents as live resources in Claude Desktop

Agent training

  • — Structured intake form feeds an analysis agent before any deployment decision
  • — Output scored against a five-dimension rubric across six model configurations
  • — Rubric evaluates: factual accuracy, specificity, cross-parameter integration, reference utility, synthesis
  • — Results determine which model and settings ship to production

Current phase

  • — First scoring session complete
  • — Runs 2–6 pending cold evaluation

How I Work with Claude

How I build tools

  • — Structured MD files for every project: instructions, architecture, schema rules, and protocols
  • — Every project starts with a CLAUDE.md that gives Claude full context before any prompt is written
  • — Claude Code runs in VS Code; every change is a diff I review before accepting
  • — Browser stays open to test live; I read every line written — to understand, not just catch errors

How I build agents

  • — Designed intake form, versioned system prompt, and a five-dimension evaluation rubric
  • — Output scored across six model configurations before any production decision
  • — One variable changes per experiment run; evaluation happens cold, the next day
  • — Prompt changes require a pattern across at least two runs before implementation
  • — The agent doesn't ship until the prompt is stable

The result

  • — Moves fast without breaking things
  • — Produces auditable output
  • — Treats AI as a system to be designed, not a tool to be prompted and hoped at

About Maxwell Perkins

Music and software development have more in common than most people think. Both are languages. Both are puzzles. You start with a problem or an idea, build a structure toward a solution, adjust as new information surfaces, and end with something that works and feels right.

I spent years as a composer and entrepreneur building that way of thinking. Running a business taught me to solve real problems for real people, not the problems I assumed they had. That discipline carried into everything I built next.

As AI tools became more accessible, I adopted them into my music and business work, then studied them more seriously through prompt engineering and data annotation at an AI lab. That work deepened a passion. Building became a hobby. When I started freelancing for Sprout Society, a Brooklyn nonprofit focused on mental wellness and community connection, I realized the hobby could become a profession.

The suite of tools I built for them is in active daily use. Since shipping, I have been deepening my technical foundation to take the work further. That foundation is growing fast.
