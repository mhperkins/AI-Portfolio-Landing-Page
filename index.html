Music Composition Assistant

In Development

Problem: AI music tools are built for non-musicians. They generate output rather than assisting the creative process, which makes them largely useless for a working composer. What's useful is a collaborator that can engage with incomplete material, ask good questions, and help think through decisions.

Approach: Building a multi-phase agent that doesn't generate music, but assists at each stage of the writing process: research and planning, analysis of musical fragments, brainstorming and critique of works in progress, and editing support during engraving. Each phase has a defined prompt architecture and a rubric for evaluating response quality.

Current phase: Running structured prompting experiments across each composition stage, grading responses against a rubric, and using emerging patterns to refine the agent's system prompt and tool design. The goal is an agent that integrates into the actual writing process without getting in the way of it.

Claude API Agent Architecture Tool Use Rubric Design Prompt Engineering

How I Work with Claude

The problem with most AI-assisted development: Without structure, Claude loses context between sessions, makes changes that break unrelated parts of the codebase, and produces output that's hard to verify. The solution is better architecture around the prompts, not better prompts.

What I built: A documentation system with structured MD files covering project instructions, backend architecture, schema rules, and workflow protocols. Every project has a CLAUDE.md that gives Claude the full picture before any prompt is written. This keeps each prompt short, focused, and grounded in the actual system.

How I work: Claude Code runs directly in VS Code. Every change is a diff I review before accepting. I keep the browser open to test changes live. I read every line that gets written, not to catch errors but to understand what's being built and why. That habit is what's building my technical depth.

The result: A workflow that moves fast without breaking things, produces auditable output, and has shipped four production tools for a real client in active daily use.

About

Music and software development have more in common than most people think. Both are languages. Both are puzzles. You start with a problem or an idea, build a structure toward a solution, adjust as new information surfaces, and end with something that works and feels right.

I spent years as a composer and entrepreneur building that way of thinking. Running a business taught me to solve real problems for real people, not the problems I assumed they had. That discipline carried into everything I built next.

As AI tools became more accessible, I adopted them into my music and business work, then studied them more seriously through prompt engineering and data annotation at an AI lab. That work deepened a passion. Building became a hobby. When I started freelancing for Sprout Society, a Brooklyn nonprofit focused on mental wellness and community connection, I realized the hobby could become a profession.

The suite of tools I built for them is in active daily use. Since shipping, I have been deepening my technical foundation to take the work further. That foundation is growing fast.
