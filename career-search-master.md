## Cover Letter Structure

### The Formula That Works
1. **Opening** — one sentence on the role and your core positioning
2. **Proof** — specific tools you've shipped, actively used in production
3. **Connection** — why this specific company/role interests you (mirror their language)
4. **Closer** — one line, portfolio link

### Cover Letter Template
```
Dear [Name/Team],

I'm applying for the [Role] role. My background sits at the intersection of 
[relevant skills from job description].

I've recently built and shipped a full internal toolset for a non-profit client 
including a CRM, grant research and writing tool, and a campaign tracking tool, 
all actively used in production today. Additionally, I do prompt engineering and 
data annotation at an AI lab, which gives me a strong foundation in how LLMs 
behave and where they fail.

[Company-specific paragraph — 2-3 sentences connecting your experience to their 
specific problem/mission. Mirror their language from the job description.]

My portfolio with live demos is at https://ai-portfolio-landing-page.vercel.app/

[Sign-off]

Maxwell Perkins
maxwellhperkins@gmail.com
925-259-1748
```

### Cover Letter Rules
- **No em dashes** — use commas, periods, or restructure the sentence
- **No time references** that sound short ("in 3 months") — just say "I've built and shipped"
- **No generic enthusiasm** — connect specifically to their problem
- **Keep it under 250 words** — hiring managers skim
- **Always attach PDF resume** when emailing directly
- **Always include portfolio link** — hyperlinked if possible

### What to Customize Per Application
- The company-specific paragraph is the only thing that changes significantly
- Mirror the exact language from their job description (ambiguous environments, human-in-the-loop, etc.)
- For mission-driven companies, add a personal connection if genuine
- For technical roles, emphasize workflow and process over just output

### The Question You Will Get Asked
**"What do you do when Claude Code gets it wrong in a non-obvious way?"**

Answer: "That's why I built the MD files the way I did. When Claude gets something wrong non-obviously it's usually missing context about how one part of the system connects to another. I learned that the hard way when UI changes were breaking backend data — so I documented the architecture explicitly so Claude always has the full picture. ## MCP Server (Build This Next)

An MCP (Model Context Protocol) server wraps the CRM's live Supabase data as tools Claude can call mid-conversation. Instead of copy-pasting data into Claude, Claude queries the database itself.

**What it exposes:**
- `get_relationship_health` — counts by status, overdue contacts, upcoming actions
- `search_contacts` — filter by name, status, relationship type
- `get_contact_detail` — full record with touchpoints and next actions
- `list_upcoming_actions` — all actions due across contacts, orgs, and events
- `list_events` — upcoming events with contact counts
- Resources: live org profile + the CRM Research Protocol markdown

**The demo conversation:**
> "What should I focus on this week for relationships?"

Claude calls `get_relationship_health`, calls `list_overdue_contacts`, reads the org profile resource, and responds with a specific prioritized answer grounded in live data. That is multi-step tool use with real production data.

**The portfolio sentence:**
> "I built an MCP server on top of a production CRM that exposes live contact and relationship data as Claude tools. Claude queries the database mid-conversation, identifies relationship gaps using custom cadence logic, and generates research briefs following the protocol I wrote — all from a single conversation."

**Why it matters for AI dev roles:** demonstrates Claude API tool use, multi-step reasoning, schema design, and real-world use case. Directly addresses the medium-term goal from this career doc.

**Build location:** `sprout-crm-next/mcp/server.js` — about 120 lines using `@modelcontextprotocol/sdk`, connects via stdio to Claude Desktop.

## What Is and Is Not a Portfolio Centerpiece

The Sprout Suite (CRM + Grant Manager + Social Manager) is the centerpiece. Three production tools, real nonprofit client, actively used.

The n8n automation is not a centerpiece. It is a learning exercise and a useful feature, but a scheduled database query + email is not impressive on its own. What makes it worth mentioning: the decision to build it in n8n to learn the tool, then convert to native code so it doesn't require a paid subscription. That shows engineering judgment.

The MCP server is a strong secondary item for AI dev roles specifically. It demonstrates Claude API depth beyond "I called the API" — it shows tool use, resource design, and multi-step reasoning with real data.

The research protocols (CRM Research Protocol, Funder Brief Protocol, Grant Finding Protocol) are undersold. Being able to say "I designed a structured prompt protocol that runs multi-phase research and outputs schema-validated JSON ready for import" is a real differentiator. Most people who "use AI" cannot articulate their prompt architecture.
